For teachers, trainers and bootcamp leads

Free for classrooms and bootcamps. Teach a real crawl in 45 minutes.

Toadstone is a free, self-hosted SEO crawler. It is source-available under the Elastic License 2.0, with 222 checks, no seat fees and no URL cap. It runs on each student's own laptop, so there are no accounts to create and no crawl data leaves the room. Below is a ready exercise: crawl a small practice site, find what is wrong, fix it, and crawl again to prove it.

Before class (10 minutes, teacher)

Do this the day before, on one machine that matches your students' laptops. A first install is the step most likely to go wrong in a class, so keep it out of the 45 minutes.

What each student needs

  • Python 3.11 or newer and git (Toadstone's README lists Python 3.11+).
  • Toadstone installed from github.com/spcaeo/toadstone. The README has three routes: Docker Compose, plain Docker, or pip install -r requirements.txt plus playwright install chromium.
  • Two terminal windows and a browser.
  • The practice site zip from the kit below.

What the exercise does not need

  • No account, e-mail address or sign-up. Anywhere.
  • No internet access during the crawl: the practice site runs on localhost, so nothing is crawled on a third party's server.
  • No paid plan, licence key or credit card.
  • No real site. Please do not point a class of 30 at a site you do not own.

Honest note: we have not yet run this with a live class. The timings are an estimate, and the crawl numbers on this page come from our own test runs of the kit with the current Toadstone code. Counts can shift by a few if your version has added or changed checks, so run the crawl yourself first and use your own numbers on the board.

The 45-minute run-sheet

Students work alone or in pairs. Every command below is for macOS or Linux; on Windows use python instead of python3.

  1. 0 to 5 minSet up

    Unzip the site and start both servers

    Unzip practice-site.zip. In terminal 1 start the practice site, which is only reachable from your own machine:

    cd practice-site
python3 serve.py

    Open http://localhost:8099/ in a browser: a tiny garden-shop site, six pages. Keep port 8099 and the host name localhost exactly, because the home page's canonical tag points there. In terminal 2, from your Toadstone folder, start the app:

    python main.py --local --port 5057

    Then open http://localhost:5057.

  2. 5 to 10 minCrawl

    Crawl the practice site

    In the Toadstone app enter http://localhost:8099/ and start the crawl. It takes a few seconds. Prefer the command line? This does the same and writes a report you can diff later:

    python main.py --crawl http://localhost:8099/ --fail-on error --report before.json

    Expected in our test run: 9 URLs crawled, 18 errors, 58 warnings, 8 info, and a non-zero exit code because of --fail-on error. That exit code is the same switch teams use to fail a build.

  3. 10 to 20 minTriage

    Sort the findings: what matters, what is noise

    Ask each pair to open the issues view and answer three questions on paper: which findings could stop a page being found or used (broken, missing, duplicate)? Which are cosmetic or advice? Which are about the practice server rather than the site (for example the server_version_disclosed and missing security-header findings, which come from Python's tiny test server)?

    Then hand out the table below, without the last column, and have them match each planted problem to a finding. Every finding in Toadstone links to a plain-English explanation and a how-to-fix note, so students should use those, not guess.

    Teaching point: severity is the tool's opinion, not a verdict. Missing structured data is labelled an error here; a missing referrer policy is only info. Ask the class whether they agree, and why a team might change the ranking.

  4. 20 to 35 minFix

    Fix the site, one problem at a time

    Students edit the HTML files in practice-site/ with any text editor and reload the browser as they go. The core fixes are the first six rows of the table below. Pairs that finish early take the stretch task.

  5. 35 to 45 minRe-crawl and discuss

    Crawl again and compare the numbers

    python main.py --crawl http://localhost:8099/ --fail-on error --report after.json

    Expected after the six core fixes: 7 errors, 38 warnings, 7 info, with every remaining error being no_structured_data. After the stretch task (add structured data): 0 errors, the run prints PASSED and exits 0. Discuss: which fixes removed the most findings per minute of work? Why did warnings go up after the stretch task (answer in the key below)? What would you want in a real pre-launch checklist?

Real before and after

From our test crawls, errors / warnings / info:

  • Start: 18 / 58 / 8 (9 URLs)
  • After core fixes 1 to 6: 7 / 38 / 7 (8 URLs: the redirecting URL is gone)
  • After the stretch task: 0 / 45 / 7, --fail-on error passes

Why warnings rose at the end

Our minimal WebPage JSON-LD has no datePublished or dateModified, so seven new missing_dates warnings ("Missing Article Dates") appeared. It is a good moment to show that fixing one thing can surface another, and that a clean "error" count is not the same as a finished site.

Honest limits for a classroom

What Toadstone does not do

  • No per-student or per-class accounts, projects or grading. Each student runs their own copy.
  • No PDF reports and no white-label output. It exports Excel, CSV, HTML and Markdown.
  • No keyword research and no rank tracking, so this is a technical-SEO exercise only.
  • The CLI has no flags yet for max URLs, delay or user-agent; the app has them.

What to watch for

  • It is young software with known false positives. Teach students to verify a finding before they report it, and never to crawl a site they do not own.
  • Licence: Elastic License 2.0 is source-available, not open source. Using it in teaching is fine. Offering it to third parties as a hosted service is not covered.
  • On a Mac, always pass --port: port 5000 belongs to AirPlay Receiver.
